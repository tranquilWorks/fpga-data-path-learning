## Model and retained deterministic contract

- Inputs: pipelineStages in 0 through 4, inputPeriod in 1 through 4, and selectedCycle in 1 through the configuration's totalCycles are finite real numeric integer scalars normalized to double after validation. brokenValidAlignment is logical or numeric 0 or 1 and is normalized to logical.
- Operand representation: signed W=4 with one sign bit, I=1 integer-magnitude bit excluding sign, and F=2 fractional bits. Operand codes scale by 1/4. Product codes are retained at Fp=4 with an LSB of 1/16 and a modeled eight-bit product path; no finite-width product or accumulator resize occurs in this model.
- Fixed input codes: [3,-2,5,1,-4,6,-1,4]. Fixed coefficient codes: [2,4,-1,3,2,-2,5,5]. Exact product codes: [6,-8,-5,3,-8,-12,-5,20]. Exact prefix codes: [6,-2,-7,-4,-12,-24,-29,-9]. The final code/value is -9/-0.5625.
- Cycle convention: an input product accepted at edge k accumulates in the post-edge state for k+L, where L is the number of registered product stages. L=0 accumulates on the acceptance edge. The model does not add a separately modeled accumulator/adder-register delay.
- Baseline: L=2 and input period 1. Tokens enter on cycles 1 through 8, accumulate on cycles 3 through 10, first accumulate at cycle 3, and complete at cycle 10. At selected cycle 5, input token 5 is offered, data/valid token 3 arrives, product code -5 accumulates, and the running code is -7.
- Pipeline-stage sweep: L=0 through 4 at period 1. First accumulation cycles are [1,2,3,4,5], completion cycles are [8,9,10,11,12], modeled product storage is zero through four values or zero through 32 bits, and every final code remains -9.
- Input-period sweep: periods 1 through 4 at L=2. Completion cycles are [10,17,24,31], pre-pipeline bubble counts are [0,7,14,21], event spacing follows the offered period, and every final code remains -9.
- Bubble contract: every invalid input slot deliberately carries legal nonzero diagnostic operand codes 7 and -8 and product code -56. Healthy valid propagation prevents this poison data from changing the accumulator, making control gating observable.
- Broken case: at L=2 and period 1, valid and its claimed token bypass the product registers while data remains delayed. The first two claims consume empty reset state, the next six consume stale products, tokens 7 and 8 are dropped, and the final code/value is -24/-1.5 rather than -9/-0.5625. All eight claims name empty or stale data.
- Broken sparse case: at L=1 and period 4, bypassed valid samples the poison bubble path; all eight real tokens are dropped and the final code is -392. The L=0 broken switch is a deliberately inert limiting case because no data delay exists to bypass.
- Accumulator contract: the fixed reference trace spans codes -29 through 6 and needs at least six signed bits. The conservative modeled width is product width plus ceil(log2(8)) = 11 bits, with code limits -1024 through 1023. No overflow occurs; this is a model bound, not measured hardware utilization.
- Resource contract: totalCycles is at most 33, productStageAfter has at most 132 stored values over the trace, the configured product storage is at most four values/32 modeled bits, and all loops and arrays are input-bounded.

The Python oracle independently reconstructs input schedules, poison bubbles, pre-edge register output, post-edge register state, delayed token/valid paths, healthy and bypassed accumulation, token loss, sum divergence, and resource bounds. It executes all 20 healthy stage/period combinations, all 16 broken combinations with L=1 through 4, L=0 behavior, dense and sparse faults, malformed inputs, recovery, and isolation. Static tests pin corresponding MATLAB formulas, accepted numeric-class normalization, control ordering, source-level absence of toolbox/opaque/stateful/external operations, and presentation separation. This still does not execute or translate MATLAB semantics.
