# P11 retained evidence — 2026-08-23

## Outcome and claim boundary

P11 — Frame Packets Across a Stream is implemented as a complete interactive MATLAB learning slice.
It extends P10's valid/ready payload hold rule to a generic `last` packet-boundary sideband, exposes
packet length and consumer stall duration independently, retains a healthy reference beside a
deliberately broken boundary counter, and finishes with executable MATLAB assertions plus an
independently implemented Python cycle oracle.

The retained evidence proves repository structure, canonical identity, source contracts,
learner-CLI behavior, and the behavior of the independent Python simulation described below.
MATLAB, Octave, and octave-cli were unavailable. This record therefore does not claim MATLAB
execution, MATLAB numerical fidelity, figure rendering, UI callback behavior, MATLAB-release
compatibility, synthesized FPGA behavior, protocol compliance, bench, HIL, field, RT1/RT2, Unreal,
signing, deployment, staging, release, or production validation.

The manifest evidence level is `simulated` because the framing state and all bounded control pairs
executed in an independent Python oracle. It is not a claim that MATLAB executed.

## Governing model and retained simulated outputs

Signals are observed immediately before an edge:

    transfer[n] = valid[n] && ready[n]
    packetEnd[n] = transfer[n] && last[n]

Payload and `last` form one offered beat. If `valid && ~ready`, both stay stable until an accepting
edge. After reset or an accepted `last`, the next accepted beat begins the receiver's next packet.

### Exact baseline

Inputs and bounds: packet length 4 beats; consumer ready low on cycles 4–6; 12 payload labels
`[0,411,822,1233,1644,2055,2466,2877,3288,3699,14,425]`; fixed 24-cycle record;
modeled 12-bit labels; packet-length choices `[2,3,4,6]`; maximum stall 6 cycles.

- Transfer cycles: `[1,2,3,7,8,9,10,11,12,13,14,15]`.
- Source-stalled valid cycles: `[4,5,6]`.
- Payload beat 4/code 1233 and `last=1` remain stable on cycles 4–7.
- Accepted beat ordinals are `1:12`; payload values and order are unchanged.
- Expected and observed boundary beat ordinals are `[4,8,12]`; accepting boundary edges are
  `[7,11,15]`.
- Completed receiver packet lengths are `[4,4,4]` beats with no trailing beat.
- Completion is cycle 15; active-window rate is `12/15 = 0.8` beats/cycle; boundary density is
  `1/4` boundaries/beat.
- Loss, duplicate, reorder, payload-hold violation, `last`-hold violation, and accepted-boundary
  mismatch counts are all zero.

### Independent sweep 1 — packet length

Consumer ready remains low for three cycles from cycle 4; payload values, transfer schedule,
allocation, and fault mode remain fixed. Packet length sweeps `[2,3,4,6]` beats.

- Completed packet counts: `[6,4,3,2]`.
- Boundary densities: `[1/2,1/3,1/4,1/6]` boundaries/beat.
- Every completed packet length equals the selected length.
- Completion remains cycle 15 and all 12 payload beats remain ordered for every case.

### Independent sweep 2 — consumer stall

Packet length remains four beats; payload values, expected boundaries, allocation, and fault mode
remain fixed. Consumer ready-low duration sweeps `0:6` cycles from cycle 4.

- Completion cycles: `12:18`.
- Source-stalled cycles: `0:6`.
- Active-window rates: `12./(12:18)` beats/cycle.
- Every case accepts boundary beats `[4,8,12]`, reconstructs `[4,4,4]`, and retains all payloads.

### Limits and deliberately broken case

- Two-beat packets/no stall: transfer cycles 1–12, boundaries `[2,4,6,8,10,12]`, six complete
  packets, completion cycle 12.
- Six-beat packets/six-cycle stall: boundaries `[6,12]`, two complete packets, six stalled source
  cycles, completion cycle 18.
- Broken baseline: payload correctly holds, but boundary state advances on each of the three
  unaccepted valid cycles. `last` changes after the first stalled cycle; accepted boundary beats
  move to `[5,9]`; complete receiver lengths become `[5,4]` with a three-beat unterminated tail;
  mismatch positions are `[4,5,8,9,12]`. All 12 payloads still arrive once, in order, on the same
  completion edge as the healthy path.
- No-stall inert limit: selecting the fault changes only its mode tag because no valid beat is
  blocked and no boundary state advances independently.
- Non-boundary hidden-state limit: with three-beat packets and one stalled cycle, beat four offers
  `last=0` both before and after the blocked edge, so the direct `last` hold-value violation count is
  zero. The broken marker state still advances once; later accepted boundaries move from
  `[3,6,9,12]` to `[3,5,8,11]`, completed lengths become `[3,2,3,3]` with one trailing beat, and
  mismatch positions are `[5,6,8,9,11,12]` while all payloads and completion remain intact.
- Whole-packet aliasing limit: with four-beat packets and four stalled cycles, illegal boundary
  drift equals one packet. Accepted boundaries realign at `[4,8,12]` and packet lengths appear
  correct, while `last` hold violations remain on cycles 5 and 8.
- All 28 packet-length/stall pairs executed for healthy and broken paths in the independent Python
  oracle. Healthy paths preserve full framing. Broken paths preserve all payloads; fault activation
  equals `stall>0`, and receiver-visible corruption occurs exactly when `stall mod packetLength` is
  nonzero. Arrays remain bounded at 24 cycles and 12 beats, with at most six packets.
